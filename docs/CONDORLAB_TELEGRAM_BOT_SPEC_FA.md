## ۱. اهداف، نقش‌ها و دامنه عملکرد در فاز A

```text
                 ▼                                ▼                                ▼
       [ ۱. پشتیبانی و تیکتینگ ]         [ ۲. کارنامه و اعلان‌ها ]         [ ۳. دانلود کتب و جزوات ]

```

## ۲. سناریوی اتصال حساب و دریافت منابع (Deep Linking & Account Binding)

### مسئله و چالش کاربری:
اگر برای دانلود کتاب در تلگرام از داوطلب بخواهیم نام، ایمیل، کلمه عبور و پایه تحصیلی را در تلگرام تایپ کند:
- تجربه کاربری (UX) خسته‌کننده می‌شود و ریزش شدید رخ می‌دهد.
- ثبت‌نام در تلگرام دوباره‌کاری پایگاه داده است و ایمیل را تایید نمی‌کند.
- هدف بیزینس (افزایش جامعه آماری کاربران ثبت‌نام‌شده روی دامنه اصلی) محقق نمی‌شود.

### راه‌حل استاندارد: جریان پیوند هوشمند (Deep Linking Flow)

```text
[ کاربر در تلگرام ] ---> دکمه «دانلود جلد ۱ کمپبل»
                                 │
                 (آیا Chat_ID قبلاً متصل شده است؟)
                        ├─── بله ───> [ ارسال مستقیم فایل PDF در تلگرام ]
                        │
                        └─── خیر ───> [ ارسال دکمه شیشه‌ای «اتصال حساب کاربری کندرلب» ]
                                                     │
                                                     ▼
                                    (لینک یک‌بارمصرف با توکن امضاشده)
                               https://condorlab.ir/auth/telegram?token=XYZ
                                                     │
                                                     ▼
                                      [ باز شدن مرورگر گوشی کاربر ]
                                      ├── کاربر لاگین است؟ ---> دکمه «تأیید اتصال» (۱ کلیک)
                                      └── کاربر لاگین نیست؟ ---> ثبت‌نام سریع (گوگل / ایمیل)
                                                     │
                                                     ▼
                                      [ ثبت Telegram_Chat_ID در دیتابیس ]
                                                     │
                                                     ▼
                                      [ ریدایرکت خودکار به تلگرام ]
                                 tg://resolve?domain=CondorlabBot&start=linked
                                                     │
                                                     ▼
                                      [ بات: «آرتین عزیز، حساب شما متصل شد!» ]
                                      [ ارسال خودکار فایل PDF درخواست‌شده ]
```

## ۳. تحلیل معماری زیرساخت: سرور خودمان یا سرورلس (Serverless Edge)؟

### چالش اساسی: فیلترینگ تلگرام در ایران
* اگر سرور اصلی کندرلب در دیتاسنترهای داخلی ایران (آسیاتک، ابرآروان و...) مستقر باشد:
  - سرور ایران نمی‌تواند مستقیماً به دامنه `api.telegram.org` متصل شود (فیلتر است).
  - تلگرام نمی‌تواند به سادگی به IPهای داخلی وب‌هوک بزند (تاخیر و قطعی مسیریابی).
* اگر کل سرور در خارج کشور باشد:
  - کاربران داخل ایران در زمان افت اینترنت بین‌الملل ممکن است دچار کندی شوند و درگاه پرداخت شاپرک به IP خارج حساسیت دارد.

### معماری پیشنهادی و برنده: هیبرید با Cloudflare Workers (کاملاً رایگان و ضد قطعی)

```text
[ سرورهای تلگرام ] 
       │ (ارسال وب‌هوک بدون فیلتر با پینگ ۵ میلی‌ثانیه)
       ▼
[ Cloudflare Worker Edge (سرورلس خارج از ایران) ]
       │ 
       ├── پردازش سریع پاسخ‌های متنی و استاتیک
       │
       └── (ارسال امن با توکن مخفی x-telegram-secret)
             │
             ▼
[ سرور اصلی کندرلب (NestJS API) ]
• بررسی دیتابیس، تطبیق کارنامه، ارسال لینک و ثبت تیکت
```

**مزایای این رویکرد:**
1. بدون نیاز به سرور واسط پرهزینه یا VPN روی سرور اصلی.
2. پایداری ۱۰۰٪ حتی در صورت اختلالات اینترنت بین‌الملل در داخل.
3. پلن رایگان کلودفلر تا ۱۰۰,۰۰۰ درخواست در روز را بدون دریافت حتی ۱ ریال پاسخ می‌دهد.

## ۴. بررسی وضعیت و شرایط استفاده از «ایموجی‌های پریمیوم» در بات تلگرام

> [!WARNING]
> **قانون رسمی تلگرام درباره ایموجی‌های پریمیوم در بات‌ها:**  
> داشتن تلگرام پریمیوم روی اکانت شخصی ادمین یا سازنده بات، **هیچ ارتباطی با قابلیت ارسال ایموجی‌های پریمیوم در بات ندارد و آن را فعال نمی‌کند!**

بر اساس مستندات رسمی تلگرام:
1. **شرط مجاز شدن بات:** یک بات تلگرام تنها در صورتی مجاز به ارسال تگ‌های `<tg-emoji>` یا موجودیت‌های `custom_emoji` در متن پیام است که **یک یوزرنیم کلکسیونی (Collectible Username) از پلتفرم Fragment (با رمزارز TON)** خریداری و به بات متصل کرده باشد.
2. در غیر این صورت، سرورهای تلگرام تمامی تگ‌های ایموجی اختصاصی ارسالی از سمت بات را نادیده گرفته و به ایموجی ساده تبدیل می‌کنند.

### راهکار جایگزین، حرفه‌ای و بدون هزینه برای فاز A:
* **استفاده از ترکیب غنی یونیکد:** استفاده از ایموجی‌های علمی و جذاب استاندارد که در همه دستگاه‌ها باز می‌شوند (🧬, ⚡, 📊, 🎯, 🔥, 🏆, 📚, 💡).
* **ساخت پک استیکر رسمی کندرلب با `@Stickers`:** طراحی استیکرهای وکتور نشان‌های مدال، لوگوی کندرلب و پیام‌های تبریک، و ارسال آن‌ها با متد رایگان `sendSticker` در کنار متن پیام‌ها.

## ۵. محل انتشار جزوات رایگان در نسخه ۱ سایت

### چالش:
در نسخه ۱ وبلاگ (`/blog`) نداریم و انتشار جزوات پی‌دی‌اف در قالب پست وبلاگی اصلاً استاندارد آموزشی نیست.

### راهکار مصوب: بخش اختصاصی «کتابخانه و منابع المپیاد» (`/resources`)
در هدر و فوتر سایت یک لینک ثابت با عنوان **«منابع و جزوات» (`/resources`)** قرار می‌گیرد:
1. **کتاب‌های مرجع المپیاد:** دانلود جلد ۱ تا ۸ بیولوژی کمپبل، بیوشیمی لنینجر، ژنتیک براون.
2. **جزوات طلایی کندرلب:** جزوات خلاصه‌نویسی دست‌نویس و تایپ‌شده اساتید مدال‌آور (متین موسوی، نیما رضایی).
3. **مکانیزم دانلود:**
   - نمایش کارت هر جزوه با تصویر جلد، حجم فایل و سرفصل‌ها.
   - دکمه **«دانلود رایگان با حساب کاربری»**: اگر کاربر وارد شده باشد، دانلود آنی شروع می‌شود؛ اگر وارد نشده باشد، مودال ورود/ثبت‌نام سریع باز شده و بلافاصله پس از لاگین دانلود انجام می‌شود.
   - هم‌زمان، لینک بات تلگرام نیز در پایین کارت قرار دارد: «دریافت مستقیم همین فایل در تلگرام».

## ۶. تغییرات موردنیاز در مدل داده (Database Schema)

برای اتصال حساب تلگرام به کاربر، فیلدهای زیر به جدول `users` در [CONDORLAB_DATA_ARCHITECTURE_FA.md](file:///Users/matinmousavi/Desktop/Condorlab/CONDORLAB_DATA_ARCHITECTURE_FA.md) الصاق می‌گردد:

```prisma
model User {
  id                 String    @id @default(uuid())
  email              String    @unique
  fullName           String
  // ... سایر فیلدها
  
  // فیلدهای یکپارچه‌سازی تلگرام
  telegramChatId     BigInt?   @unique
  telegramUsername   String?
  telegramLinkedAt   DateTime?
  
  // تیکت‌های پشتیبانی تلگرام
  supportTickets     SupportTicket[]
}

model SupportTicket {
  id             String    @id @default(uuid())
  userId         String
  user           User      @relation(fields: [userId], references: [id])
  channel        String    @default("telegram") // telegram | web
  subject        String
  status         String    @default("open")     // open | pending | closed
  createdAt      DateTime  @default(now())
  updatedAt      DateTime  @updatedAt
}
```
